# 汉堡包计划 · Hamburger Plan

[English](README.md) | **中文**

> 把新习惯挂在每天雷打不动的那件事后面。

一个单文件 PWA：不按钟点提醒，而是让新习惯跟着每天本来就会发生的事走——起床后就做，午饭前做，洗完澡做。这就是习惯叠加（habit stacking），「汉堡包」是面包夹肉饼的意思：固定的那件事是面包，新习惯是中间的肉饼。

**在线试用**：https://hamburger-plan.app.workbuddy.host/

用 Safari 打开这个链接，添加到主屏幕，就跟装了个 App 一样，不用上架应用商店。

> **公开的是哪个版本**：这份是**单机版**。记录只存在你自己这台设备的浏览器里（`localStorage`），不登录、不向任何服务器发送一个字节。所以它没有多端同步——想要同步，得自己接一个后端。这也是刻意的：一个谁都能写的线上实例，访客的每次写入都记在所有者账上。

---

## 为什么做这个

习惯类应用大多有两个毛病。

**一是按钟点安排。**「每天早上 7:30 冥想」听起来清楚，实际执行起来，7:30 你在别的事上，于是错过、于是那天作废。人对「几点几分」这种约定是很迟钝的；对「午饭前」是很敏感的。

**二是考核感。**连续打卡天数、完成率、断了几天——这些数字让人一旦断了就不想再打开。而习惯这件事，断了接着做就行，本来不需要被记过。

所以这个应用的取舍很明确：**锚点代替时间点，记录代替考核。**

## 它能做什么

| 想做的事 | 怎么做 |
| --- | --- |
| 记下每天固定会发生的事 | 加**锚点**：起床、午饭、下班进门、洗澡。选哪几天、填个大致时间（只用来排序） |
| 把新习惯挂上去 | 加**事项**时选「挂在哪个锚点后面」，它每天就出现在那个锚点下面 |
| 一天要做好几次 | 在「一天要做几次」里填 `8 杯` 这种，它会进今天页顶部的**习惯**栏，点一下加一次 |
| 打勾 | 点卡片右侧那一小条就行，不用精准戳中那个圈（整张卡片高度都算） |
| 换挂载点 | 按住卡片不松手，拖到别的锚点后面；拖到「未分配」＝今天先不做 |
| 太忙的日子 | 给事项留一句「最忙时的最小版」，忙的时候只做这一步 |
| 删掉 | 在汉堡页往左滑，露出红色「删除」 |
| 看做得怎么样 | 回顾页：按月点阵，颜色越深那天做得越多；点某一天看明细；再往下看这一年每个月做了几次 |
| 换手机 / 防丢 | 设置里导出备份（一个 `.json` 文件），新设备上用「从备份恢复」灌回去 |
| 离线用 | 加到主屏幕即可，Service Worker 缓存了页面、字体和图标 |

## 几个设计取舍

**锚点不设提醒。** 真正的触发器在你生活里（午饭、洗澡），不在通知栏。定时推送反而会把「跟着事件走」悄悄换回「跟着表走」，那是这个应用想避开的做法。

**完成之后会被收进「已完成」，但计数型不会。** 普通事项打勾后移到下方「已完成」区，让今天的剩余事项保持干净。但一天要喝 8 杯水的那种，如果每喝一杯都被收走，等于一天要把它拖回来 8 次——所以它单独占今天页顶部一栏，到量只变绿，留在原位。

**「一天几次」是一个可选字段，不是第二种实体。** 没有新增「习惯」对象、没有新增「这是习惯还是事项」的开关：填了次数就是计数型，不填就是打一次勾。数据上只是多了 `target: {times, unit}` 和一个旁挂的每日计数，历史记录的结构一个字没动。

**只数次数，不算完成率。** 回顾页回答的是「这个月我做了几天」，不是「我达标了 87%」。没有连续天数，断了也不显示断了几天。

**打勾热区比圈大得多。** 25px 的圈要求精准命中，差几个像素就落进「打开编辑页」，在手机上是灾难。现在卡片右侧约五分之一、整张卡片高度都算打勾。

**长按才拿得起来。** 卡片平时是列表，按住 460ms 才进入拖动，避免滑动时误拖。

## 数据存在哪

全部在浏览器本地，两个键：

- `hb_state` —— 整份存档（锚点、事项、每天的打卡、碎碎念）
- `hb_dirty` —— 待推送的时间戳队列（给未来的同步留的口子，现在只写不消费）

容量约 5 MB 一个站点，到 3 MB 会提示。实际占用很小：打卡一天几十字节，十年也就一百多 KB，真正占地方的是碎碎念。写盘失败（比如存储满了）会明确提示，不会假装存上了。

因为只在本地，数据**跟着这台设备的这个浏览器走**：换手机看不到，换个浏览器打开是空的，清掉网站数据就没了。所以设置里留了导出 / 导入。

## 技术

- **单文件**：`index.html`（约 2900 行，HTML + CSS + 原生 JS，零框架、零依赖、无构建步骤）
- **PWA**：`manifest.webmanifest` + `sw.js`，导航请求网络优先（保证更新），字体图标缓存优先
- **字体自托管**：全部按实际用字子集化成 `woff2` 放在 `fonts/`，不挂任何字体 CDN——国内环境下 CDN 连不上会静默掉回系统字体，看不出错
- **动画**：打勾后卡片滑到新位置用 FLIP（先记坐标、重绘后反向位移再归零），而不是淡出

## 本地运行

```bash
python3 -m http.server 8000
# 打开 http://localhost:8000
```

Service Worker 只在 `http(s)` 下生效，`file://` 直接双击打开不会有离线缓存（其余功能正常）。

## 目录

```
index.html              整个应用
sw.js                   Service Worker
manifest.webmanifest    PWA 清单
fonts/                  子集化字体（woff2）
icons/                  图标
build_public.py         从主项目构建这份公开单机版（见下）
```

**`build_public.py`**：主项目的开发版将来会接云同步，仓库里这份必须永远是零云端的。所以它不是手工复制出来的，而是每次从主项目重新构建：复制文件 → 把设置页的「云同步」改成单机版说明 → 自检（无网络调用、无外链、无本机路径），不通过就退出。
